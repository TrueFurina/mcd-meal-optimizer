## 版本 A：朋友圈 / 群聊（口语版，约 130 字）

> 花了一晚上用麦当劳 MCP 写了个「算盘」——不是帮你挑套餐，是在
> 「热量区间 + 蛋白下限 + 预算上限」三重约束下**求最优解**。
>
> 实测：550–800 大卡、蛋白≥30g、预算 40 元 → 蘸酱麦麦脆汁鸡 + 蘸酱炸鸡，
> **¥23.80 / 656 kcal / 蛋白 42g**。而且下单前用官方接口复算，还是 ¥23.80，一分不差。
>
> 正在参加麦当劳的开发者大赛，求个 Star 🙏
> https://github.com/TrueFurina/mcd-meal-optimizer

## 版本 B：技术群（工程视角，约 200 字）

> 分享一个用麦当劳 MCP 做的练手项目：**麦麦算盘**。
>
> 核心不是"推荐个套餐"，是把点餐建模成**双约束动态规划** ——
> state=(热量桶, 蛋白桶, 必需掩码)，value=最低到手价（含券）。
> 因为求解器是纯函数，所以能拿穷举做 **120 组随机差分验证**，结果必须完全一致，
> 还能做变异验证（故意改错，测试必须红）。
>
> 几个实测下来挺坑的点：`query-meals` 价格是「元」而 `calculate-price` 是「分」，
> `create-order` 又变回「元」；套餐营养要自己从 `rounds[].choices[].isDefault=1` 拆；
> 菜单名和营养库名对不上（薯条 → 中薯条），改用详情精确名后覆盖率 58/121 → 82/121。
>
> 零第三方依赖，64 项测试。大赛参赛中，Star 就是票数 🙏
> https://github.com/TrueFurina/mcd-meal-optimizer

## 版本 D：针对"AI 会不会瞎编"的钩子（适合技术群/知乎）

> 问 AI「麦当劳三件套多少卡」，它大概率给你一个听着合理的数字 —— 但你没法验证。
>
> 区别在于：**数据是从麦当劳 MCP 实时取的，还是模型记忆里猜的。**
>
> 我做了个反例：麦辣鸡腿汉堡三件套 = **921 kcal / 蛋白 28g**，
> 这个数是把套餐拆成「麦辣鸡腿汉堡 + 中薯条 + 可乐中杯」逐项求和算出来的，
> 不是估的。缺营养数据的餐品直接排除出解，**绝不按 0 计算假装达标**。
>
> https://github.com/TrueFurina/mcd-meal-optimizer
